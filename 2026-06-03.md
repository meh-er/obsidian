## (a) What is a critical section? (4)
The critical section is a section of code that executes and can change the state of memory, potentially causing data inconsistencies. If a second process enters its critical section while a first process is inside it, this can cause issues such as race conditions, crashes, and more.

## (b) Why is it so difficult to find synchronisation errors? (4)
Synchronisation errors may only occur when two processes execute in a specific order, it may not happen everytime you run the code, so it can be very hard to catch and potnetially not show up during testing at all.

# Q3
## (a) During context switching, the operating system replaces the currently executing process in the CPU by a new one. Why is it important for the operating system to avoid too many context switches and let a process run for a sufficient amount of time before another context switch? (4)
If there is not enough of a gap between context switches, and they occur too often, this can cause overhead, where the CPU is unable to actually execute any processes, i.e. do any useful work during the time of a context switch. Therefore, the amount of throughput would significantly decrease, and it would be incredibly inefficient, potentially unable to work at all. Therefore to avoid this, operating systems should let a process run for a sufficient amount of time first, to increase throughput.

## (b) Which steps are performed by the operating system during context switching? (4)
The OS saves the state of the process currently in context inside the PCB, this incldues infromation such as its state, memory usage, process id, program counter, etc.
The OS then loads up the PCB or new process that is taking over and puts it into the CPU 

## (c) What is the primary difference between paging and segmentation? (4)
Paging splits into pages of fixed size, all the same size, does not allow for external fragmentation (holes in memory over time) since in pages, pages can be loaded in and out of storage, useful
Segmentation splits into sections based on what it does e.g. code, data, etc, less efficient, does allow for external fragmentation.
